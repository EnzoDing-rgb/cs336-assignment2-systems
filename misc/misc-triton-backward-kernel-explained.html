weighted_sum_backward 内核导读

先弄清 launch grid → program_id → 缓冲区下标；再读代码。本页用 NUM_ROWS=4, ROWS_TILE_SIZE=2, D=4 作例。

0 · 你说的「in-place 加」和 partial 的关系

写到不同地址 → 内核里不撞车
grad_x：program 0 写行 0–1，program 1 写行 2–3 → 各写各的格子，直写最终缓冲区。
partial_grad_weight：program 0 写缓冲区第 0 行，program 1 写第 1 行 → 内核里也不撞车。
写的是「部分和」，不是最终答案 → 内核外还要 reduce
partial_grad_weight[0,j] 只含 X 行 0–1 对 grad_weight[j] 的贡献；
partial_grad_weight[1,j] 只含行 2–3。要得到真正的 grad_weight[j]，必须在 Python 里 sum(axis=0)。
这不是因为两 program 往同一地址 atomic 加，而是因为故意分了「部分和槽位」。

1 · 三个名词（先读这里）

n_row_tiles
把矩阵 X 的行方向 切成几块，一共几块。
不是 X 里的某一行号；是「行块的总个数」。
本例 = cdiv(4, 2) = 2
row_tile_idx
= tl.program_id(0)：当前这个 program 负责第几块行块（从 0 编号）。
本例只有 0 和 1 → 手算里的「实例 0 / 实例 1」。
0 → X 行 0–1；1 → X 行 2–3
tl.num_programs(0)
launch 时 grid 第 0 维的长度 = 一共起了几个 program。
Python 写 [(n_row_tiles,)]，所以这里恒等于 n_row_tiles。
本例 = 2
Q：n_row_tiles 到底是哪个 row？
A：哪个都不是。它是计数：行方向被 tile 切成了几块。类比：一条 4 米长的面包切成 2 段，n_row_tiles=2 说的是「有 2 段」，不是说「第 2 行面包屑」。
Q：row_tile_idx 就是实例 0 / 1 吗？
A：在本例（2 个 program）里，是。row_tile_idx=0 就是第 0 个 program（管行 0–1），=1 是第 1 个 program（管行 2–3）。一般情况可有 0…n_row_tiles−1。
Q：为什么 num_programs(0) == n_row_tiles？
A：因为你 launch 时就按这个数起的 program 个数：weighted_sum_backward[(n_row_tiles,)]。Triton 在轴 0 上启动 n_row_tiles 份内核副本；num_programs(0) 只是把这同一个数字读回来，用来声明 partial_grad_weight 第 0 维有多大。

3 · partial_grad_weight 的第 0 维 = 行块号（不是 X 的行号）

partial_grad_weight[?, j]列0列1列2列3含义
行块 0…………只累加 X 行 0–1
行块 1…………只累加 X 行 2–3
sum ↓grad_weight[j] = partial[0,j] + partial[1,j]Python，内核外

shape=(n_row_tiles, D) 里 n_row_tiles 来自 num_programs(0)，就是为「每个行块留一行部分和」。 offsets=(row_tile_idx, 0) 保证 program 0 只写第 0 行槽位，program 1 只写第 1 行槽位。
