1. 第一性原理：缺什么，所以要通信

一张卡要算一层线性层：y = x @ W。算式本身要求完整的 W（或等价的完整视图）。

Why shard parameters at all？
DDP / 作业里的 ShardedOptimizer：每卡仍常驻完整 W，只切 OPT（和可选切 G）。 FSDP 再进一步：平时每卡只存 W 的 1/N 分片。于是「要算 matmul」和「平时只存分片」矛盾 → 算之前必须 all-gather 临时拼出完整 W；算完立刻丢掉完整视图，只留分片。
Why reduce-scatter gradients？
每卡本地 batch 不同 → 算出的完整 dW 是局部的。 更新时每卡只负责自己那一截参数（和分片形状对齐）→ 不需要每人留完整平均 G， 用 reduce-scatter：归约 + 按分片分发，每卡只留下自己那截梯度。
Why hooks？
你不会在 model.forward 里手写「第 3 层前 gather、第 3 层后 free」。 层是嵌套调用的；autograd 反传顺序也由图决定。 Hook = 挂在「层即将算 / 刚算完 / grad 刚写好」上的回调，让通信自动插入正确时刻。
Why handles（Work）？
async_op=True 时集合通信立刻返回一个 dist.Work，GPU/后台继续传， CPU 可以先去干别的（算别的层）。 Handle = 这张「未完成通信」的收据；必须在用到结果之前 wait()， 否则读到的还是半成品。

你的大图是对的：Forward 按层 all-gather P → 算 → 丢；Backward 倒序 all-gather P → 算 G → reduce-scatter → 丢完整 P。 补一句：小层（讲义里主要是 norm）不切，整份复制，省去无意义的通信延迟。

2. 和「只切 OPT」差在哪（同轴加深）

ShardedOptimizer（作业）FSDP（本题）
平时存的 W完整分片（Linear/Embedding）
平时存的 G完整（step 只用分片）分片（reduce-scatter 后）
OPT分片自然跟参数分片走（AdamW 只看到分片 param）
前向要通信吗通常不用为了 W每层（被切的）all-gather W
后向要通信吗DDP 侧常 all-reduce G再 all-gather W + reduce-scatter G
对齐新 Wbroadcast / all-gather 整模不必每人再拼完整常驻 W；常驻仍是分片

3. Hook 和 Handle：代码层面各是什么

3.1 Hook（钩子）——「事件回调」

登记发生在 FSDP.__init__；执行发生在之后的 forward/backward 途中，由 PyTorch 调用你。

钩子 API何时被调FSDP 典型用途
mod.register_forward_pre_hook(fn) 进入该层 forward 之前 wait 本层权重 all-gather；确保 weight.data 已是完整视图
mod.register_forward_hook(fn) 该层 forward 之后 丢掉完整 W，写回分片；按预取规则启动更深层的 all-gather
mod.register_full_backward_pre_hook(fn) 该层 backward 之前 再次 all-gather（或 wait 预取）完整 W，供算 dX/dW
param.register_post_accumulate_grad_hook(fn) 该参数 .grad 刚累加完 对完整（或临时）grad 做 async reduce-scatter；把 handle 存起来 
# 登记长什么样（概念）
layer.register_forward_pre_hook(self._fwd_pre)          # fn(module, inputs)
layer.register_forward_hook(self._fwd_post)             # fn(module, inputs, output)
layer.register_full_backward_pre_hook(self._bwd_pre)    # fn(module, grad_output)
weight.register_post_accumulate_grad_hook(self._grad_hook)  # fn(param)

# 执行时不是你调的：是
#   loss = model(x)           → 一路触发 forward_* hooks
#   loss.backward()           → 倒序触发 backward / grad hooks

3.2 Handle（Work）——「异步通信收据」

# 发起（不阻塞到传完）
handle: dist.Work = dist.all_gather(..., async_op=True)
# 或
handle = dist.reduce_scatter_tensor(..., async_op=True)

self._handles.append(handle)   # 先记在本子上，继续算别的

# 必须在「读结果」之前
handle.wait()                  # 阻塞到这次通信完成
# 现在 buffer / param.grad 分片才安全可读

和 OverlapDDP 的关系

你已写过的 OverlapDDP：grad hook 里 all_reduce(..., async_op=True) → 存 handle → finish_gradient_synchronization 里 wait。 FSDP 同一套路，只是通信换成 all-gather(W) / reduce-scatter(G)， 并且 forward 路径上也要 wait/prefetch。

5. 公开接口（讲义 + adapters）

接口谁实现职责
FSDP.__init__(module, compute_dtype=None) 你的类 包装模型；分片；挂钩；可选混合精度策略
FSDP.forward(*args, **kwargs) 你的类 转发给 self.module；通信靠 hooks，不塞在这里手写每层
FSDP.finish_gradient_synchronization() 你的类 wait 所有未完成的 reduce-scatter（及必要的遗留通信）
get_fsdp(...) adapter return FSDP(...)
fsdp_on_after_backward(fsdp, opt) adapter 通常只调 fsdp.finish_gradient_synchronization()
fsdp_gather_full_params(fsdp) adapter / 类方法 测试比对：把分片 all-gather 成完整 tensor 字典；norm 原样返回

测试假定包装器上有 fsdp_model.module（与 DDP 习惯一致）。

6. 一步训练：时间线（4 卡直觉）

时间 →

  [构造] 每卡 Linear.weight 只留 shard（约 1/4）
         RMSNorm.weight 完整复制（不进 FSDP 切分）

  [Forward 层 i]
     ① 若预取已发出：forward_pre 里 handle.wait()
     ② weight 临时变成完整（可先 cast → compute_dtype 再 AG，省带宽）
     ③ 计算 y = f(x, W_full)
     ④ forward_post：删掉 W_full，写回 shard；按规则 prefetch 层 i+2 的 AG

  [Backward 层 i （倒序）]
     ⑤ bwd_pre：再次具备 W_full（wait 或同步 AG）
     ⑥ autograd 算出完整形状的局部 dW（相对本卡 batch）
     ⑦ post_accumulate_grad_hook：
          async reduce-scatter → 每卡 .grad 变成「自己那截」
          handle 进列表；可 free W_full
     ⑧ 激活梯度继续往更浅层流

  [after backward]
     ⑨ finish_gradient_synchronization：全部 handle.wait()
     ⑩ optimizer.step()：Adam/SGD 只碰本地 shard
「算完就丢」丢的是临时完整视图，不是把本地 shard 删掉。 Master 分片始终在；完整 W 是租来的缓冲区。

7. 钩子时刻表（单层被切模块）

Forward
  1. forward_pre
  2. 保证完整 W 就绪（wait handle）
  3. 层自身 forward 计算
  4. forward_post
  5. free 完整 W；kick 更深层 prefetch
Backward
  1. full_backward_pre
  2. 完整 W 就绪
  3. autograd 算 dW / dX
  4. post_accumulate_grad
  5. async reduce-scatter；存 Handle；free W

混合精度（compute_dtype 非 None）

讲义：通信前就 cast 到低精度 → 少传字节；master 与 OPT 仍 FP32。

  • AG 前：shard.to(compute_dtype)（或在 buffer 上）再 all-gather
  • 计算用低精度完整 W
  • reduce-scatter 后的 grad 再回到 FP32，与 master shard 对齐（测试要求 grad dtype == param.dtype）

测试里非并行基线用同一套 cast hook（_apply_mixed_precision_hooks）对齐数值行为。

8. 预取规则（讲义硬约束）

原文要点：只有当「当前层前面两层」的 forward 已经完成时，才开始 gather 当前层权重。 也就是：在层 i 的 forward 之后，去预取层 i+2（而不是立刻把后面所有层都 gather 满显存）。 

层序（被切的）:  L0  L1  L2  L3  L4 ...

L0 forward_post ──prefetch──► 开始 AG(L2)
L1 forward_post ──prefetch──► 开始 AG(L3)
L2 forward_pre  ──wait─────► AG(L2) 必须已完成
...

Why：通信与计算重叠，又限制「同时存在的完整 W」数量（大约维持一小窗口，而不是整网完整副本）。

9. 写代码前：函数职责清单（内部要点，不写满）

建议内部方法要点
_shard_parameters() 对 Linear/Embedding 的 weight：按 dim 切成 N 份，本 rank 只保留一块；记录 shard_size / 全 shape，供 AG/RS
_register_hooks() 只对要切的模块挂 4 类钩子；norm 跳过
_all_gather_weight(mod, async_=True) → Work|None 从各卡 shard 拼到临时 full buffer；可选先 cast；返回 handle
_wait_and_install(mod) wait 该层 handle；把 mod.weight.data 指到完整视图（或 copy）
_free_full_weight(mod) 恢复为本地 shard 视图；释放 full buffer
_prefetch(mod_index) 对 index+2（若存在）发 async AG，存 handle
_reduce_scatter_grad(param) → Work async RS；结果写入与 shard 同 shape 的 param.grad
finish_gradient_synchronization drain handles；必要时做平均（若 RS 用 SUM）
gather_full_params() 同步 AG 所有分片参数 → dict[name, Tensor]；复制参数直接 .data.clone()
两种常见结构任选其一（讲义允许）： (1) hooks 挂在原 Linear/Embedding 上； (2) 换成包装模块（包装器自己的 forward 里 gather→compute→free）。 测试只关心行为与 .module / adapters，不规定必须哪种。

# 与非并行模型参数 allclose

写代码顺序建议

  1. 骨架：FSDP(nn.Module) + self.module + forward 转发
  2. 分片 + 同步 all-gather/reduce-scatter（先不做 async / prefetch）— 先过正确性
  3. 换成 async + handles + finish_gradient_synchronization
  4. 加 prefetch（layer-2 规则）
  5. 加 compute_dtype
  6. 接上三个 adapters
