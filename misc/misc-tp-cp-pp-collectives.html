1. TP（Tensor Parallel）——切「同一个 token 的特征宽度」

切哪根轴：同一个样本、同一个 token，它的特征向量沿 d_model（或 FFN 的宽）切开， 多张卡各算一块，再合成完整结果。
对照：不是把不同 token 分给不同卡（那是 CP）；也不是把不同层分给不同卡（那是 PP）。

场景（4 卡 TP，以「行并行 matmul → 需要求和」为例）

目标算 Y = X · W。把 W 按行切开成 WA, WB, WC, WD， 每张卡同时把输入的对应切片乘自己的权重块，得到局部贡献：

本地算完之后 = 上图 All-Reduce 的「通信前」

YA = XAWA
GPU B
YB = XBWB
GPU C
YC = XCWC
GPU D
YD = XDWD

完整输出是四块贡献之和： Y = YA + YB + YC + YD。 下一层还要在每张卡上继续用完整的 Y，所以必须让每张卡都拿到完整 Y。

为什么是 All-Reduce，不是 All-Gather？
因为四张卡算出来的是「同一形状张量上的加法贡献」，不是「可以拼起来的不同列」。 加法 → 需要 Reduce；人人都要完整结果 → 需要 All-Reduce。

这不是另一种数学结果，而是把一次 All-Reduce 拆成两步，好在中间塞计算。 最终仍然等价于「每人一份完整 Y」。

2. CP（Context / Sequence Parallel）——切「不同 token 的序列位置」

切哪根轴：沿 seq_len 切开。每个 token 的特征向量完整留在一张卡上； 不同卡负责序列上不同的 token 段。
和 TP 的一句话差别：TP 是「同一个 token 被拆开」；CP 是「不同 token 住在不同卡」。

Attention 规则：每个 query token 要和序列里所有 key 做点积。 但 GPU A 本地只有 token 0–1 的 K，看不到 2–7。所以必须先把各卡的 K（以及 V）拼齐。

V 同理。之后：GPU A 用自己的 Q（token 0–1）× 全局 K/V，算出自己那段输出 OA；其他卡同理。

为什么这里是 All-Gather，不是 All-Reduce？
因为各卡手里是「序列上不同位置的 K」，要拼成一条长序列，不是对同一位置做加法。 拼接 → All-Gather。

阶段 2：继续以分片形式往下走 —— 常用 Reduce-Scatter

后面若某层又产生了「每张卡都有一份对完整输出的贡献、但下一层只想按序列分片持有」， 就会用 Reduce-Scatter：先按位置求和，再让每张卡只留下自己负责的那一段序列。

这样 CP 可以一直维持「每卡只存自己那截序列」，显存按序列长度摊薄。 若某处必须完整 O，再 All-Gather 一次即可。

3. PP（Pipeline Parallel）——切「层的深度」

切哪根轴：沿模型深度切开。GPU A 跑层 0–7，GPU B 跑层 8–15……
关键：PP 不用 All-Reduce / Reduce-Scatter / All-Gather 这类「全体集合通信」。 它只用相邻 stage 之间的 P2P send / recv。

4 卡 Pipeline 长什么样

GPU A

── send 激活 ──▶
GPU B
层 8–15
── send 激活 ──▶
GPU C
层 16–23
── send 激活 ──▶
GPU D
层 24–31

前向：A 算完自己的层，把边界激活发给 B；B 算完再发给 C……
反向：梯度沿相反方向，D → C → B → A，同样是相邻点对点。

为什么这里没有那三种集合原语？
因为任意时刻，数据只需要从「上一截层」流到「下一截层」。 不存在「四张卡同时对同一张量求和」或「四张卡互相拼齐同一份 K」这种全体协作。 通信拓扑是一条链，不是一个环上的全体集合。

4. 一图对照：TP / CP / PP

切什么 一张卡上，一个 token 的向量？ 典型通信 为什么是这种通信
TP 特征宽 / 矩阵宽（同一 token 被切开） 被拆开，分住在多卡 All-Reduce（或 RS+AG） 各卡算出的是加法贡献，且人人要完整结果
CP 序列位置（不同 token 分到不同卡） 完整，但只覆盖自己那段序列 All-Gather（拿全局 K/V）+ 常配 Reduce-Scatter Attention 要看全局上下文 → 先拼；之后常继续按序列分片持有
PP 层深度（不同层住在不同卡） 完整（在当前 stage 的层里） P2P send/recv，不用三种集合原语 数据只需沿层链前后传，不需要全体卡对同一张量规约/拼接
记法口诀：
  • 求和且人人要完整 → All-Reduce（TP 最常见）
  • 只拼接、不求和 → All-Gather（CP 拉齐 K/V）
  • 求和但每人只要一段 → Reduce-Scatter
  • 只跟邻居传激活 → P2P（PP）
