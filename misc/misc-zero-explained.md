# ZeRO 技术说明（用具体数字把流程跑一遍）

> 目标：不假设你还记得术语。每个概念都用小数字走一遍「运行时长什么样」。  
> 最后再对照：作业里的 `ShardedOptimizer` 和 ZeRO stage 1（\(P_{os}\)）各自在干什么。

---

## 0. 先固定一个玩具场景（全文共用）

假设：

- **4 张 GPU**：编号 rank 0, 1, 2, 3  
- 模型权重一共 **8 个数**（想象已经拍扁成一条向量）  
  \[
  W = [w_0,w_1,w_2,w_3,w_4,w_5,w_6,w_7]
  \]
- 每张卡做 data parallel：各自有一份 batch，backward 后各自得到一份梯度  
  （一开始可以先想成「每卡都有完整的 8 个梯度」，后面再讲切开）

Adam 类优化器对**每个权重**通常还要存状态，粗算大约：

- 参数 \(W\) 本身：8 个数  
- 一阶矩 \(m\)：8 个数  
- 二阶矩 \(v\)：8 个数  

若 **4 卡每卡都存全套**（朴素 DDP）：

| 东西 | 每卡份数 | 4 卡合计 |
|------|----------|----------|
| \(W\) | 8 | 32 |
| \(m\) | 8 | 32 |
| \(v\) | 8 | 32 |

优化器状态很贵。ZeRO 的思路：**别每人存全套，切开存。**

论文里用符号标记「切了什么」：

| 符号 | 英文直觉 | 切的是什么 |
|------|----------|------------|
| \(P_{os}\) | Partition **O**ptimizer **S**tates | 切优化器状态（\(m,v\) 等） |
| \(P_{g}\) | Partition **G**radients | 再切梯度 |
| \(P_{p}\) | Partition **P**arameters | 再切参数本身 |

ZeRO 的阶段大致是叠加：

- **Stage 1** = 只有 \(P_{os}\)  
- **Stage 2** = \(P_{os} + P_{g}\)  
- **Stage 3** = \(P_{os} + P_{g} + P_{p}\)（和 FSDP 很像）

下面先把通信算子用数字跑通，再讲各 stage。

---

## 1. 三个集合通信：运行时长什么样

以下都假设 4 卡。重点看「开始每卡有什么 → 结束每卡有什么」。

### 1.1 All-reduce（求和后再平均：DDP 梯度常用）

开始：每卡有长度为 4 的向量（举小一点好算）

```text
卡0: [0, 1, 2, 3]
卡1: [4, 5, 6, 7]
卡2: [8, 9, 10, 11]
卡3: [12, 13, 14, 15]
```

All-reduce **SUM** 之后，每卡都变成逐位置的和：

```text
每卡: [0+4+8+12, 1+5+9+13, 2+6+10+14, 3+7+11+15]
    = [24, 28, 32, 36]
```

若再 ÷4 得到平均：

```text
每卡: [6, 7, 8, 9]
```

**结果形态：** 每人最后都有**同一份完整结果**。

---

### 1.2 Broadcast（一个人说了算，覆盖别人）

开始：

```text
卡0: [10, 10, 10, 10]   ← 假设这是「权威」新值
卡1: [0, 0, 0, 0]
卡2: [0, 0, 0, 0]
卡3: [0, 0, 0, 0]
```

执行：`broadcast(tensor, src=0)`

结束：

```text
每卡: [10, 10, 10, 10]
```

**结果形态：** 所有人变成和 **src** 那张卡一样。  
作业 `ShardedOptimizer.step` 末尾对每个参数做的，就是这种（`src=owner`）。

---

### 1.3 Reduce-scatter（先归约，再每人只留一块）

把长度 4 的向量切成 4 块，每块 1 个数：位置 0 / 1 / 2 / 3。

开始（每卡都有完整 4 个数）：

```text
卡0: [0, 1, 2, 3]
卡1: [4, 5, 6, 7]
卡2: [8, 9, 10, 11]
卡3: [12, 13, 14, 15]
```

Reduce-scatter **SUM** 的目标：

- 位置 0 的全局和，最终主要落在卡0  
- 位置 1 的全局和 → 卡1  
- 位置 2 → 卡2  
- 位置 3 → 卡3  

全局和仍是：

```text
位置:  0→24,  1→28,  2→32,  3→36
```

结束时（示意，每人只「拥有」自己那一块的最终和；其它位置可丢掉/不管）：

```text
卡0 持有: [24]      # 只关心位置0 的全局和
卡1 持有: [28]      # 只关心位置1
卡2 持有: [32]
卡3 持有: [36]
```

**结果形态：** 总和算完了，但**拆开存放**——每人只拿齐自己负责的那一段。  
和 all-reduce 比：all-reduce 是「每人拿齐全部总和」；reduce-scatter 是「总和按块分给不同人」。

---

### 1.4 All-gather（每人贡献一块，最后每人凑齐全部）

开始（每人只有自己那一块）：

```text
卡0: [24]
卡1: [28]
卡2: [32]
卡3: [36]
```

All-gather 之后：

```text
每卡: [24, 28, 32, 36]
```

**结果形态：** 从「各持一块」变回「每人完整一份」。

常和 reduce-scatter 配成一对：

```text
完整多份输入
  --reduce-scatter--> 每人一块（已归约）
  --（本地计算）-->
  --all-gather------> 每人又有完整结果
```

## 2. 朴素 DDP：每卡全套都存

仍用 8 个权重、4 卡。

每卡内存里大致有：

```text
W:  [w0..w7]     # 完整参数
G:  [g0..g7]     # 完整梯度（本地 backward 后；再 all-reduce 平均）
m:  [m0..m7]     # Adam 一阶矩
v:  [v0..v7]     # Adam 二阶矩
```

一步：

```text
1) 各卡用自己的 batch 算 forward/backward → 得到本地 G
2) all-reduce 平均 G → 每卡 G 相同，仍是 8 个数
3) 各卡用完整 (m,v) 对完整 W 做 Adam 更新
   （各卡算出来的新 W 应一致，因为 G 已一致、状态若一开始一致）
```

问题：\(m,v\) 每卡全存，显存随「模型大小」涨，不随「切卡」变少。

---

## 3. ZeRO Stage 1 = \(P_{os}\)：只切优化器状态

### 3.1 \(P_{os}\) 四个字在说什么

**Partition Optimizer States**：把 \(m,v\)（以及其它优化器状态）按卡切开。

约定：8 个权重按下标切成 4 段，每段 2 个：

```text
分片0 (归卡0): 下标 0,1
分片1 (归卡1): 下标 2,3
分片2 (归卡2): 下标 4,5
分片3 (归卡3): 下标 6,7
```

### 3.2 每卡存什么（Stage 1 典型画面）

```text
卡0:
  W: [w0..w7]          # 参数仍完整（算 forward/backward 要用）
  G: [g0..g7]          # 梯度仍完整（或先完整再处理，见下）
  m: [m0, m1]          # 只存自己分片的优化器状态
  v: [v0, v1]

卡1:
  W: [w0..w7]
  G: [g0..g7]
  m: [m2, m3]
  v: [v2, v3]

卡2 / 卡3: 同理，只养自己那 2 个下标的 m,v
```

和朴素 DDP 比：\(W,G\) 仍然每卡一份完整；**省的是 \(m,v\)**（大约省到原来的 \(1/4\)）。

### 3.3 一步可以怎么跑（一种常见 ZeRO-1 调度）

用数字串起来：

**A. Backward 结束，假设 all-reduce 后每卡梯度都是：**

```text
G = [1, 1, 1, 1, 1, 1, 1, 1]   # 只是举例用的数
```

（有的实现会用 reduce-scatter，让卡0只留下 `[g0,g1]` 的归约结果；这里先用「先有完整 G」好懂。）

**B. 各卡只用自己的 \(m,v\) 更新自己分片的 \(W\)：**

```text
卡0: 用 (m0,m1),(v0,v1) 和 (g0,g1) 更新 → 得到新的 w0', w1'
卡1: 更新 → w2', w3'
卡2: → w4', w5'
卡3: → w6', w7'
```

此时各卡上的完整 \(W\) **不一致**：每卡只有自己那两维是新的，别人的维还是旧的。

**C. 把参数分片收齐（ZeRO-1 常用 all-gather）：**

开始（示意每人贡献自己刚更新的两维）：

```text
卡0 贡献: [w0', w1']
卡1 贡献: [w2', w3']
卡2 贡献: [w4', w5']
卡3 贡献: [w6', w7']
```

All-gather 后：

```text
每卡 W: [w0', w1', w2', w3', w4', w5', w6', w7']
```

下一轮 forward 又可以用完整新权重了。

### 3.4 若梯度侧用 reduce-scatter 会多一步什么样

Backward 后每卡先有完整本地梯度，例如：

```text
卡0 本地 G: [0,1,2,3,4,5,6,7]
卡1 本地 G: [10,11,12,13,14,15,16,17]
...（卡2、卡3 略）
```

对 \(G\) 做 reduce-scatter（按 4 段、每段 2 个数），结束后：

```text
卡0 只持有「下标 0,1 的全局归约梯度」: [g0_sum, g1_sum]
卡1 只持有下标 2,3 的归约梯度
...
```

然后卡0用这两维梯度更新 \(w0,w1\)，再 all-gather 参数。  
这样 step 前不必在每卡保留完整归约后的 \(G\)（更省通信/显存的变体）；**经典 Stage 1 名字仍叫 \(P_{os}\)，实现细节可以带这种梯度调度。**

---

## 4. ZeRO Stage 2 = \(P_{os}+P_{g}\)：再切梯度

在 Stage 1 基础上：梯度也按同样分片存。

```text
卡0 长期主要保留: G 的 [g0,g1]，以及 m,v 的对应两维
卡1: [g2,g3] + 对应 m,v
...
```

更新仍是「我只更新我的两维 \(W\)，再 all-gather \(W\)」。  
和 Stage 1 比：连「完整 \(G\)」也不用每卡常驻了。

---

## 5. ZeRO Stage 3 = \(P_{os}+P_{g}+P_{p}\)：参数也切开

参数本身也只存分片：

```text
卡0 只存: [w0, w1]
卡1 只存: [w2, w3]
...
```

Forward/backward 前要用某层完整权重时，先 **all-gather** 临时拼出来，用完再丢掉。  
这和作业后面的 **FSDP** 同一类思想。本文不展开层调度。

---

## 6. 作业 `ShardedOptimizer` 运行时长什么样（同一套 8 个数）

构造时（`i % 4` 归属，示意）：

```text
卡0 的本地 AdamW 管: w0, w4
卡1 管: w1, w5
卡2 管: w2, w6
卡3 管: w3, w7
```

（具体下标依赖实现；这里只为说明「每人管 2 个」。）

每卡内存：

```text
W: 完整 8 个（模型上）
G: backward 后通常完整 8 个
m,v: 只为「自己管的 2 个」建
```

`step` 时：

```text
1) 本地 AdamW.step()
   卡0 只改 w0, w4
   卡1 只改 w1, w5
   ...

2) 对每个参数做 broadcast(src=owner)
   例如:
     broadcast(w0, src=0)  → 四人的 w0 都变成卡0 的新值
     broadcast(w1, src=1)  → 四人的 w1 都变成卡1 的新值
     ...
```

结束后每卡 \(W\) 再次完整且一致。

## 7. 并排放在一起：一眼看差在哪

同一场景：4 卡，8 权重。

| | 朴素 DDP | ZeRO-1 \(P_{os}\)（典型） | 作业 ShardedOptimizer |
|--|----------|---------------------------|------------------------|
| 每卡 \(W\) | 完整 | 完整 | 完整 |
| 每卡 \(G\) | 完整 | 完整，或 reduce-scatter 后只留分片再更新 | 完整（step 时只用自己分片的 grad） |
| 每卡 \(m,v\) | 完整 | **只有分片** | **只有分片** |
| 更新后如何对齐 \(W\) | 往往已各自算出相同 \(W\)（因 \(G\) 已 all-reduce） | 常见：**all-gather** 参数分片 | **多次 broadcast**（每个参数 `src=owner`） |
| 名字 \(P_{os}\) | 未切 OPT | 是 | 目标同类（切 OPT），实现更朴素 |

用通信「结束形态」对比对齐权重那一步：

**ZeRO-1 常见 all-gather：**

```text
开始每人两维新值 → all-gather → 每人八维完整新 W
```

**作业 broadcast：**

```text
对 w0: src=0 覆盖全体
对 w1: src=1 覆盖全体
…
→ 每人八维完整新 W
```

两边最后都是「每人完整新 \(W\)」；中间用的集合通信不一样，梯度是否 reduce-scatter 也不一样。

## 8. 一张极简时间线（只记这个也行）

```text
朴素 DDP:
  完整W, 完整G, 完整OPT
  → all-reduce G
  → 每人用完整OPT更新完整W

ZeRO-1 (P_os):
  完整W, (完整或分片)G, 分片OPT
  →（可选 reduce-scatter G）
  → 每人用自己的OPT更新自己的W分片
  → all-gather W分片 → 完整W

作业 ShardedOptimizer:
  完整W, 完整G, 分片OPT
  → 每人用自己的OPT更新自己的W分片
  → 按owner broadcast 各参数 → 完整W
```

## 9. 术语速查（对应上面的数字戏）

| 词 | 运行时一句话 |
|----|----------------|
| All-reduce | 每人投入完整向量 → 每人拿回同一份聚合结果 |
| Broadcast | 指定 src 的向量 → 覆盖所有人 |
| Reduce-scatter | 每人投入完整向量 → 每人只拿走聚合结果的一块 |
| All-gather | 每人投入一块 → 每人凑齐全部块 |
| \(P_{os}\) | 切优化器状态 |
| \(P_{g}\) | 切梯度 |
| \(P_{p}\) | 切参数 |
| ZeRO stage 1 | 基本上就是 \(P_{os}\) |

读完若只记一句：

> **\(P_{os}\) = 优化器状态切开；Stage 1 仍常留完整参数。作业版同类省显存，但对齐权重用 broadcast，且不按论文那套梯度 reduce-scatter/参数 all-gather 日程来写。**
